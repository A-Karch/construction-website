# Домен .ee и HTTPS

Используйте домен, которым управляет компания. Для коммерческого сайта добавьте домен в панели выбранного хостинга и примените DNS-записи, которые он выдаст. После выпуска сертификата включите перенаправление с HTTP на HTTPS. Для предпросмотра на GitHub Pages действует порядок ниже.

## Привязка домена предпросмотра к GitHub Pages

1. В настройках аккаунта GitHub откройте **Pages** и подтвердите свой домен с помощью TXT-записи GitHub. В репозитории откройте **Settings → Pages → Custom domain**, введите домен и сохраните.
2. Для корневого домена задайте четыре A-записи `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`. Для поддомена, например `www`, используйте CNAME на `a-karch.github.io` без пути. Допустимые записи AAAA и альтернативы описаны в документации GitHub. [Настройка DNS для GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)
3. Дождитесь подтверждения DNS и выпуска сертификата. В **Settings → Pages** включите **Enforce HTTPS**. Запустите workflow повторно, чтобы он собрал сайт с новым адресом.
4. Проверьте прямой вход на `/et/`, `/ru/`, `/en/`, загрузку изображений и canonical. Рабочий workflow получает адрес из GitHub, поэтому базовый путь меняется автоматически.

## Канонический адрес коммерческой сборки

Укажите в `websiteDomain` полный адрес, например `https://example.ee`. Если задана переменная `SITE_URL`, сборка использует её. Выполните `npm run build` и разместите новый `dist/`. Canonical, hreflang, Open Graph, Schema.org и sitemap обновятся при сборке. Проверьте доступность `/sitemap.xml` и `/robots.txt` на конечном адресе, затем добавьте домен в Google Search Console. [Подтверждение домена в Google](https://support.google.com/webmasters/answer/9008080)
