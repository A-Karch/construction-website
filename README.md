# Строительная компания · ET / RU / EN

Исходный код сайта для строительной компании в Эстонии. React, TypeScript, Vite, Tailwind CSS и Lucide. Каждая языковая страница генерируется в отдельный HTML-файл. Маршрутизация использует обычные ссылки и локализованные адреса. Контент, меню и переключатель языка работают без JavaScript. Маленький клиентский скрипт сохраняет язык и обрабатывает подключённую форму.

Текущий режим — публичный предпросмотр. Услуги предварительные, изображения подписаны как иллюстрации, форма отключена. Страницы содержат `noindex`. На GitHub Pages размещается предпросмотр исходного проекта. Для приёма заявок используйте хостинг, условия которого разрешают коммерческий сайт. [Правила GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## Локальный запуск

Требуется Node.js 22.13+ или 24.

```sh
npm ci
npm run typecheck
npm run lint
npm run build
npm test
npm run preview
```

Откройте адрес, который выведет Vite. Чтобы локально воспроизвести проектный путь GitHub Pages, задайте `SITE_URL=https://a-karch.github.io/construction-website` перед сборкой и запустите `npm run preview -- --base=/construction-website/`. В PowerShell переменную можно задать командой `$env:SITE_URL = 'https://a-karch.github.io/construction-website'`.

Сборка помещает HTML, ресурсы, карту сайта, robots.txt и 404.html в `dist/`. Без абсолютного адреса сборка пригодна для просмотра, а sitemap не содержит URL. Скрипт `npm test` проверяет содержимое уже собранной папки.

## Данные компании

Основной файл — [src/company.ts](src/company.ts).

- Подтвердите рабочее название `name` и написание имени в `contactPerson`. Заполните `phone` (с международным кодом), `email`, `address` при наличии публичного адреса, `serviceAreas`, `registrationNumber` и `socialLinks`. Контактные поля отображаются после заполнения. Телефон и почта автоматически получают ссылки.
- Поместите логотип и изображения в `public/media/`. В `logo` и `hero` укажите имена файлов. `hero.social` используется в карточках Open Graph. Снимайте признак `demo` только для проверенных материалов. В комплекте сгенерированные изображения для демонстрации.
- В `services` подтвердите только реально доступные направления (`confirmed: true`) и проверьте тексты на трёх языках. В коммерческой сборке неподтверждённые услуги скрываются. После индексации согласуйте перенаправления при смене slug.
- В `projects` замените примеры фотографиями с разрешением на публикацию. Укажите местоположение, описание, тип и alt-тексты на трёх языках. В коммерческой сборке примеры с `demo: true` скрываются.
- В `privacyPolicy` внесите согласованный текст политики для ET, RU и EN. Каждая версия — массив пар заголовок/абзац. Общие переводы находятся в `src/copy.ts`.
- Задайте `websiteDomain`, например `https://example.ee`. Сборка использует `SITE_URL` с приоритетом над этим полем. После заполнения данных, проверки текстов и выбора хостинга переключите `preview` в `false` в версии для коммерческого запуска.

## Публикация

При каждом push в `main` GitHub Actions запускает проверки, сборку и разворачивает статический предпросмотр. В **Settings → Pages → Build and deployment** источником выберите **GitHub Actions**. Workflow берёт публичный адрес из `configure-pages`. URL с подпапкой репозитория поддерживается и для ссылок, и для ресурсов. Коммерческую сборку размещайте отдельно. На её хостинге настройте раздачу файлов `index.html` из каталогов и ответ HTTP 404 с `404.html` для неизвестных путей.

## Перед коммерческим запуском

1. Подтвердите данные и регион обслуживания, перечень работ и тексты на ET, RU и EN.
2. Замените демонстрационные проекты, добавьте логотип и утверждённые изображения.
3. Согласуйте политику конфиденциальности, настройте форму и проверьте доставку тестовой заявки.
4. Разверните коммерческую сборку на выбранном хостинге с HTTPS. Проверьте телефон, почту, форму, canonical, hreflang, sitemap и ответ 404.
5. Подтвердите сайт в Google Search Console, отправьте sitemap и оформите Business Profile при наличии права на профиль.
